# 编辑器使用指南

## 先准备文件

先备份要修改的游戏资源。PAC 模式直接打开 `.pac`，不必提前解包；如果手头已经
是普通文件夹，在右上角切换到“解包模式”。本程序支持 FPAC v1，不是所有游戏的
同名 `.pac` 格式都可以打开。

### 工具放在哪里？

完整解压后运行 `TIS_Retext.exe`，保留同目录的 `_internal`。程序数据默认写到
工具旁边的 `TIS_Retext_Data`，请选择本地可写、路径较短的目录。中文目录可以使用，
目录名包含 `BaiduNetdiskDownload` 也不等于不能使用；普通下载文件夹和虚拟挂载盘不是一回事。

`0.1.3.dev20260917` 起，Windows 工作区锁不再要求硬链接。旧版本如果出现
`.lock-…tmp -> lock.json` 的 `WinError 1`，请更新工具；它不是 PAC 内容损坏的证明。
若更新后仍提示缓存目录创建、写入或锁定失败，请检查该目录是否只读、仅在线占位，
或者由特殊挂载软件管理；可先将完整工具移到本地普通目录。无需因此重新下载游戏资源。

需要单独指定程序数据目录时，可在 PowerShell 中启动（把示例路径改为自己的路径）：

```powershell
$env:TIS_RETEXT_DATA_DIR = 'D:\TIS_Retext_Data'
& 'D:\Tools\TIS_Retext\TIS_Retext.exe'
```

该设置只作用于从此 PowerShell 启动的程序，不修改系统设置。它改变整个程序数据根目录，
不会自动搬迁旧缓存，也不要求把游戏 PAC 一起移动。请先正常关闭旧实例并导出需要保留的修改。
不要盲目删除 `lock.json`、格式化磁盘或关闭安全软件来绕过报错。

## 修改一段文本

1. 点击“打开 PAC”，可以同时选择多个包。
2. 展开左侧文件夹。单击文件可以预览；双击 `.tbl` 或 `.dat` 进入“单文件”。
3. 在“查找”中输入文字并按 Enter；↓/Enter/F3 查下一个，↑/Shift+Enter/Shift+F3
   查上一个，到头后循环。同一条文本中的多次出现也会分别定位。查找和替换输入框位于同一行。
4. 双击“当前文本”单元格修改。Enter 确认本次编辑，Shift+Enter 换行，Esc 取消。
   选中一行后按 F2 也可编辑。确认单元格不等于已经生成 PAC。
5. 点击“保存修改”（Ctrl+S）。PAC 模式保存到当前工作区；解包模式写回普通文件。
6. PAC 模式还需要选择左侧对应 PAC，点击“导出 PAC”，保存到一个新的输出位置。

### 长文本如何查看

- 预览和单文件表格保留原有换行，并按列宽自动换行。每条记录单独计算高度，
  最多为普通行高的 5 倍；超出部分用“……”提示，不会删掉实际内容。
- 单文件查找会在“当前文本”中显示命中词附近的摘要并标亮命中词。
  双击该单元格或按 F2，打开全文并选中对应位置；滚轮可继续阅读全文。
- 预览页也可直接双击文本条目，进入单文件的对应行查看全文。
- 批量结果中的“原文本 / 新文本”只显示本次命中附近的上下文，随列宽调整。
  双击文件名或文本单元格均可跳到单文件全文中的对应命中。
  如果扫描后源内容有变化，不能唯一定位时会提示重新搜索。
- 拖动表头分界线可以调整列宽，行高会重新计算。正文超过高度上限时不需要
  把整张表撑高：打开该单元格即可阅读或编辑全部文字，Esc 退出且不修改。

关闭程序会清理当前会话的工作区。存在未导出的修改时会提醒，只有确认不需要这些
修改时才应放弃。已导出的 PAC 和提取出的独立文件不会随会话清理。
成功导出后，直接关闭不会再次提示“尚未构建回包”；此后再次修改、放弃某项修改
或移除新增文件，会被视为相对上次导出的新变化，需要重新导出。文件树中的
“已修改”表示与源 PAC 不同，并不表示尚未导出；再次导出仍会包含这些修改。

## 一次替换多处文字

1. 在左侧选中 PAC、文件夹或多个文件（Ctrl/Shift 多选）。进入“批量”页，点击
   “添加左侧所选范围”；也可通过资源树右键菜单“加入批量处理范围”。
2. 在替换映射中点击“新增”，双击填写旧文本、新文本。勾选“启用”控制是否参与。
   “完全匹配”只匹配整条文本；不勾选则匹配其中的子串。新旧文本相同标注“未变更”，可定位但不写入。
3. 用“上移 / 下移”或 Alt+↑/↓ 调整映射顺序，支持多选行。规则按从上到下执行，
   后一条规则会看到前一条规则替换后的文本。例如 A→B 在前、B→C 在后，最终 A 会变为 C。
4. 点击“查找匹配”，查看命中并取消不需要的项。同一段内多次出现的文字会分别列出。
   对照表展示该步骤的输入和单次替换结果，不一定是最初原文或全部规则执行后的最终文本。
5. 点击“替换勾选项”。成功项已保存，错误项会留在结果和日志中。
   调整规则文字、顺序或启用状态后必须重新查找。若取消前序命中使后续规则的预期输入改变，
   该文件会拒绝写入；请修改映射/范围后重新查找，不会猜测新的替换位置。
6. PAC 模式点击“导出 PAC”；解包模式已经写回目标文件。

“导入/导出映射”保存新旧文字规则。“导入/导出处理选择”保存扫描后逐次勾选的结果，
两者不是同一种文件。只想重复使用规则时选择前者。

结果整行按写回能力着色：绿色为原位写回，蓝色为结构重建，橙色为风险回退，
红色为不可写，灰色为未变更。取消勾选后整行改为白底，写回能力文字仍保留。
鼠标选中行时暂时显示统一选择色，这与是否勾选是两个状态。
操作按钮随可用宽度排列为一行或多行；拖动分隔条可给对照表更多空间。
“导出选择”后的“关闭”会清空本次结果、逐行勾选选择及日志，返回预览；保留替换
映射和处理范围，不撤销已经写入工作区的修改。再次处理需要重新查找匹配。

## 在全部已打开资源中查找

左侧只有一个搜索框，用旁边下拉选项切换“文件名 / 正文”，共用 ↑/↓ 按钮。

- 文件名：按文件名片段定位左侧树中的文件，不把文件夹名当作文件名命中。
- 正文：只读搜索当前模式下全部已打开的 TBL/DAT，不局限于当前选中的文件。
  后台逐个解析，找到首条即打开单文件中的局部摘要，同时继续搜索其他文件。
  搜索期间可用 ↑/↓ 在已找到的结果中循环；新增结果不会抢走当前查看的位置。
  状态栏显示已找到的数量和扫描进度。完成后继续复用完整结果循环定位。
  双击当前文本即可阅读全文；如果某些文件无法解析，会明确提示搜索范围不完整。
- Enter 向下、Shift+Enter 向上。查找不执行替换；资源、引擎或查询变化后重新搜索。
  开始编辑、保存或启动其他扫描/构建任务时，会停止尚未完成的正文搜索，以免使用过期结果。

与左侧搜索不同，“单文件”页的查找和替换只作用于当前编辑文件。

## 版本对比与扫描修复

版本对比的旧、新文本会加粗变化的部分，例如“约书亚 / 约修亚”中的“书 / 修”。
长文本只展示差异附近的摘要，实际内容和比对结果不会被截断。

“扫描与修复”仍需要可信的同版本参考来判断静默错链；无参考扫描只能发现显式
结构问题。扫描按文件更新进度，复用已解析的结构和指针对齐结果，不再为每个待扫
条目反复落盘、解析。修复仍保留非文本结构、当前文本池及输出回读检查。
激进策略可能撤销开发者主动改变的正确关系，不应只为消除差异而开启；修复另存后
仍需要游戏内测试。

## 提取、替换和插入包内文件

这些操作适用于图片、音频、模型、文本及其他包内文件，不局限于 TBL/DAT。

双击左侧 PAC 名进入“包内文件”页，也可以直接选择此页，在页内下拉框切换已打开
的 PAC，或点击“打开 PAC…”。双击文件夹进入，点击“上一级”或 Alt+↑ 返回；
筛选框只筛选当前文件夹。列表显示类型、当前内容大小及修改状态，文件夹大小是内容总和。

| 操作 | 在包内文件页中选择什么 | 结果 |
| --- | --- | --- |
| 提取所选 | 一个文件 | 选择另存路径，提取该文件的当前内容 |
| 提取所选 | 文件夹或多个文件 | 选择输出目录，保留完整包内路径；Ctrl/Shift 可多选 |
| 替换文件 | 恰好一个文件 | 选择外部文件，保留原包内路径，以外部内容替换 |
| 插入文件 | 先进入目标目录，不必选择文件 | 选择一个或多个外部文件，确认包内目的路径后加入 |

也保留左侧树的右键快捷操作；从左侧选择整个 PAC 可一次提取全包。

单个插入文件可以在路径对话框中重命名，也可以输入新目录，例如 `asset_sc/image/new.dds`。
多个文件插入时填写共同的目标文件夹，文件名沿用外部文件名；留空放到 PAC 根目录。
重名、大小写冲突、文件/文件夹冲突以及不安全路径会被拒绝。同名文件请使用“替换文件”。

批量提取不会覆盖已存在的输出文件，建议选择空目录。单文件另存时按系统对话框确认
是否覆盖。提取优先使用当前工作区已保存的内容，因此可以先修改或替换，再提取。

替换/插入会复制外部文件到工作区，随后改变外部文件不会改变已导入的版本。
文件树会显示“已修改”或“新增”。完成后点击“导出 PAC”，检查输出后再用于游戏。
“放弃修改”会撤销对应 PAC 当前会话的修改，不是删除原 PAC。

注意：插入一个资源文件不会自动生成游戏对它的引用。DDS 格式、音频编码、脚本调用
与资源路径仍需符合游戏要求；PAC 重建通过不等于游戏一定能够显示或播放该资源。

## 显示与设置

Windows 打包版声明 Per-Monitor V2 DPI 感知，高 DPI 下使用原生像素渲染；移动到
不同缩放比例的显示器时会重新计算字体和表格布局。程序内的界面缩放仍单独有效。
运行缓存默认位于 exe 旁的 `TIS_Retext_Data`，源码运行使用项目内 `.runtime`。

PNG/DDS 预览、模型贴图和字体图集会自动识别 LZ4 压缩封装，只在内存中解压，
不会改写原 DDS 或把预览解压结果回包。

在“设置”中调整界面缩放，支持 67%、75%、85% 的缩小以及 100%～200% 的放大。
100% 会结合 Windows 当前 DPI。字体和行高同步变化，
不用再通过修改系统缩放来避免表格文字被截断。左右分隔条可以拖动；长表格可横向滚动。

TBL 默认 Kuro，DAT 默认 Legacy，游戏版本默认自动识别。一般不用改引擎、Schema
或调试选项。“允许启发式回退写入”是异常格式的风险选项，不是正常文本变长的前提，
不要为了跳过报错随意打开。

快捷键：Ctrl+O 打开资源，Ctrl+F 查找，Ctrl+S 保存修改，Ctrl+Shift+S 导出 PAC
（解包模式为另存当前文件）。

## 文本里的特殊标记

`<#E[...]#M_...#B_...>` 这类字符串在当前原版解压后的资源字节中就存在，抽样对比
Legacy 与 Kuro 解析结果也保持一致，因此不能仅因包含长串数字就认定为乱码或解析错误。
编辑器保留完整原文，不会自动清除这类标记。它们各字段的游戏端具体含义尚未完整验证，
修改台词时应保留不打算改动的标记；不要把它们作为“冗余文本”批量删除。
