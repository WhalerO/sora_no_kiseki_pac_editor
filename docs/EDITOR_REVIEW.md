- 批量取消勾选行改为白底，保留写回能力标签；“关闭”释放当前扫描结果和勾选行为，
  保留映射、范围及已保存的工作区修改。鼠标选中状态与勾选状态独立。
- 版本对比使用可见单元格池，加粗共同前后缀之间的差异片段，长文展示差异附近摘要。
  字符差异计算为线性时间，不对整篇报纸反复做序列比对。
- 扫描移除只读条目的落盘再读取；扫描/单文件修复共享计划；相同载荷仍实际解析结构，
  只省去无意义的重新对齐；重复指针目标映射使用单次调用内缓存。修复后结构与文本池
  检查继续保留，算法不依赖某版原始文件的预设 SHA-256。
- PAC 状态区分“与原包不同”和“与最近成功导出不同”。另存不清除前者，避免再次
  导出时丢修改；关闭仅按后者提醒。导出失败、之后的编辑/撤销/新增项移除仍需导出。
  最近输出丢失或大小/时间戳变化，也不会被视为可安全销毁的已导出工作区。

## 2026-09-15：服务与布局审查

本次范围是 TIS_Retext 编辑器，不涉及 TIS_Retext_Patcher / TIS_Voice_Patcher。
重点检查 `RetextService`、`DocumentSession`、批量保存、TBL/DAT 写回边界、
FPAC 读写、工作区与文件树，以及桌面常用操作。没有重写已经验证的二进制解析引擎。

## 主要发现与处理

| 发现 | 处理 |
| --- | --- |
| 字体按 DPI 放大，表格仍使用固定行高；部分文本列与侧栏仍按固定像素布局 | 字体度量驱动行高，侧栏跟随 DPI/缩放，窄列按标题/内容字体度量设置 |
| PAC 载入后分隔条重置会把侧栏压窄，按钮文本和搜索框被截断 | 保留侧栏宽度保护，并将最小宽度和首选宽度放到同一 DPI 标尺 |
| 底部状态栏、映射操作按钮在内容拥挤时被挤出窗口 | 先给状态栏和操作区预留空间，列表使用剩余区域；简化映射操作和批量结果列 |
| 引擎、调试选项与大量内部说明占用常用编辑区 | 收到设置窗口；主页、单文件和批量页只保留必要的操作提示；错误与风险提示保留 |
| 单文件会话依赖各引擎发布后再作最终回读，部分引擎会就地更新传入文档 | 会话层使用文档副本，暂存输出经过最终验证后才发布，失败保留原文件和待编辑状态 |
| 原 PAC 层只允许替换既有条目，工作区把非文本缓存始终视为只读 | 增加显式导入记录及新增条目，普通媒体预览仍只读；新资源可预览、提取、重建 |
| 撤销新增条目会使工作区缓存编号有空洞，重建后的密集编号可能指向别的缓存 | 重建后按实际条目重建缓存关联，重新绑定正在编辑的新增文档 |
| 多个空文件可能共享偏移，导致数据顺序有歧义 | 为零字节载荷保留一个间隔字节，大小字段仍为零，回读校验保持严格 |
| 名称逐字节读取、每插入一个文件都写清单 | 名称改为有界块读取；整组外部文件校验和复制完毕后仅发布一次清单 |

## 保留的安全边界

- DAT 精确引用重定位和非文本结构验证继续保留，不能仅凭文字回读通过就发布。
- TBL 仍按结构引用图保存，不使用全文件按数值/字节搜索替换。
- 非文本资源不会进入文本批量替换；只有明确导入的资源才进入输出 PAC。
- 路径穿越、大小写重名、Windows 不安全文件名、文件/文件夹冲突会被拒绝。
- 提取不能把单个条目覆盖到源 PAC；目录提取遇到已有目标先拒绝，不会先写一半再发现重名。
- 外部输入先复制为工作区私有载荷。丢失已修改载荷时不静默提取原版充当修改版。
- 哈希用于当次内容一致性和外部更新检测，不与固定游戏版本白名单比较。

## 长文本搜索与行高补充修复

- 原搜索摘要固定保留前后各 42 字，不考虑字体宽度，窄列可能在命中词之前就被截断；
  整条文本匹配时也没有限制命中段长度。现在按单元格实际像素宽度保留局部上下文，
  计入粗体命中的宽度，两侧以及过长命中内部以“……”表示省略。
- 批量文本覆盖层原先只有单击事件，底层双击也只接受文件名列。现在两处都接入
  全文定位，保留原扫描的具体出现位置；源内容改变后仅在唯一匹配时重新定位。
- 原预览先压平换行再截成 180 字，单文件表格也使用截断字符串。
  新增 `AdaptiveTextTable`，保留完整值，仅显示层进行换行和有界裁剪。
  Tk 8.6 的原生 Treeview 只能统一设置行高，因此仅这两张正文表改为虚拟绘制。
  每行由可见列的最大内容高度决定，上限为当前字体普通行高的 5 倍。
- 布局只度量当前视口需要的条目，滚动到新区域再补算；滚动条范围随已度量行高更新。
  换列宽/缩放会重新排版并保留顶部条目；6000 条长文本测试中，初次绘制只度量视口内的行。
- 全文跳转使用原字符串偏移，不使用摘要偏移；覆盖 NFC、大小写折叠、非 BMP 字符，
  并测试跳到末行、编辑取消、全文保留与单条变长后的高度更新。
- 界面实测还发现批量扫描后的文件树选择恢复事件会切回预览；现在抑制排队的恢复事件，
  搜索结果页不再被抢走。预览信息与操作提示分行，避免长路径挤掉提示及提取按钮。
- 实测原版 `t_books.tbl`：利贝尔通信短标题与长正文使用不同高度；搜索正文末段的
  “柔软性”，在 1200 像素宽窗口中能看到局部摘要，双击单文件摘要及批量结果均能
  打开完整正文并选中该词。扫描使用新旧文字相同的只查找规则，未执行资源替换。
- 本次只涉及显示与导航，没有更改游戏文本、文本映射或二进制写回算法。

## 2026-09-16：操作流程、顺序替换与性能复审

改动前快照：`4bbfc5c`。范围仍仅为 TIS_Retext 编辑器。

- 原批量逻辑将全部规则同时匹配原文本，调序不能表达 A→B→C 链式替换。
  服务增加显式 `ordered=True`，GUI 的首次扫描和写后复扫都使用此路径。
  每条规则基于上一条结果计算；单条规则只执行一遍，不因替换内容包含旧词而死循环。
  默认 API 仍保留旧版同时替换语义，避免隐式改变其他调用方。
- 扫描记录保留规则序号，选择方案把序号纳入身份；映射变化后禁止使用旧清单执行。
  如果取消前序命中使后续输入变化，停止该文件而非用过期偏移猜测写入；其他文件的
  成功/失败仍分别统计，不宣称整个多文件任务具备原子提交。
- 批量保存原先只防止暂存开始后的外部修改，现在也比较载入时的源字节，避免
  解析与暂存之间的外部更新被旧文档覆盖。不使用游戏版本固定 SHA 白名单。
- 原对照表滚动时销毁/新建可见单元格控件、重复度量并重填全部文本，还监听绘制
  引发的 Expose。现在只监听布局/滚动事件，16ms 合并更新，复用控件池，
  有界缓存 1024 个局部摘要；未变化的控件不重填文本。
  回归测试跨 27 行滚动始终复用同一组 6 个可见控件，静止重绘不再计算摘要。
- 写回颜色/文字集中在 `batch_display.py`，Treeview 整行与文本覆盖层使用同一来源，
  勾选变化不覆盖能力标签。两端相同显示“未变更”，不伪装成待写入项。
- 独立 `pac_files_view.py` 管理资源浏览，目录索引无需提取载荷；实际提取/替换/插入
  仍调用原工作区服务。新增紧凑工具栏独立组件，按真实按钮宽度换行。
- 左侧搜索合并一个框，选择文件名/正文并共享上下方向键。正文搜索放在独立只读
  服务中，不污染批量的完整性状态；TBL 使用 PAC 内逻辑名选择 Schema，
  不把数字缓存文件名作为 Schema 身份。单文件搜索按实际出现位置循环，保留
  Unicode NFC/大小写折叠后的原文偏移。
- 增加 67%/75%/85% 缩放，文件树显示大小，单文件查找替换同排，映射支持多选调序。
